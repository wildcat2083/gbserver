The gbserver memory debugger

Look inside a running game, change its memory, find where it keeps a value, and stop it on the exact instruction you care about. This guide covers every part of the debugger and walks through real examples in Pokémon Red.

Opening it

On the player page, press Start, Select, Start, Select, A, B, A, B within five seconds. Any input works:

  • Keyboard: Enter or W for Start, Shift or Q for Select, Z or A for A, X or B for B.
  • On-screen buttons on a phone or tablet.
  • A gamepad.

A "DEBUG MODE" banner flickers and the debugger window opens. Close it with the × in its title bar or Esc. Entering the sequence again reopens it where you left off.

The buttons also reach the game, so you might pause or open a menu in-game while entering the code. Keyboard presses don't count while you're typing in a text box, such as the chat.

The debugger needs a ROM to be running on the pyboy engine. If a ROM is set to Boytacean, the status reads "Needs the pyboy engine"; switch it in the ROM library.

The window

The debugger looks like BGB's classic grey window. On a computer you can drag it by its title bar. On a phone it fills the screen.

Toolbar

  • Pause / Continue stops the game between frames, or resumes it. When the game is stopped, the button reads Continue.
  • Step frame runs exactly one frame and stops again. It only works while the game is stopped.
  • Status shows Running, No ROM running, or why the game stopped (for example "Stopped at breakpoint 00:01B0").

While the game is stopped, the title bar turns red, and the player page shows "Paused by debugger" to everyone connected.

If you aren't the controller, the toolbar says "view-only". You can still look around and search; see Sharing a session.

Tabs

  • Memory: view and edit bytes.
  • Search: find where the game stores a value.
  • Breakpoints: breakpoints, watches, and frozen values.
  • CPU: registers and flags.

Typing numbers

Addresses and values are hexadecimal everywhere, like BGB. You can write them several ways:

You typeMeans
D347, $D347, 0xD347, D347hHex $D347
#150Decimal 150 (hex $96)
01:4A2FAddress $4A2F in ROM bank $01 (breakpoints only)

Use # when you're typing a number you read on the game screen, such as HP or an item count.

Memory tab

A hex view of the Game Boy's 64 KB address space, refreshed a little over twice a second. Each row shows an address, 16 bytes (8 on a phone), and the same bytes as ASCII text.

Moving around

  • Type an address in the box at the top left and press Go or Enter. The byte at that address is selected.
  • Pick a Region to jump to the start of ROM, VRAM, cartridge RAM, work RAM, and so on. The memory map explains each.
  • Use ▲ / ▼ to move a page, or scroll with the mouse wheel over the grid.
  • With a byte selected, the arrow keys move the selection and Page Up / Page Down move a page.

Reading the grid

  • 7F Changed since the last refresh
  • 7F Selected byte
  • 7F Frozen
  • 7F Watched
  • 7F Breakpoint
  • 7F Next instruction (PC), while stopped

Red numbers flickering in a region show you what the game is updating right now, which is often the quickest way to spot timers, positions and animation counters.

Below the grid, the selection line shows the selected byte in hex, decimal and binary, plus the 16-bit value made from it and the next byte:

$D16D = $2C (44, 00101100b) 16-bit: $002C (44)

Editing a byte

  1. Click a byte to select it.
  2. Type two hex digits. You can also double-click the byte, press Enter, or click Edit to open the editor first.
  3. After the second digit, the value is written and the editor moves to the next byte, so you can type a run of bytes in one go.

In the editor, Enter writes and stops, Tab writes and moves on, and Esc cancels.

Writing several bytes: Poke

Put the start address in the Poke box and the bytes next to it, separated by spaces or commas (99 99 99), then click Write. Up to 256 bytes at a time.

Buttons under the grid

  • Edit opens the editor on the selected byte.
  • Freeze holds the selected byte at its current value every frame.
  • Watch pauses the game when the selected byte changes.
  • Break here sets a breakpoint on the selected byte. It only works in ROM.

What you can't edit: ROM ($0000-$7FFF) is read-only. Writing there on a real cartridge doesn't change the game; it tells the cartridge to switch memory banks, which would scramble the game. Writes to I/O registers ($FF00-$FF7F) are allowed, but they act on the hardware (sound, graphics, timers) and can have odd effects.

Changes take effect immediately, but the game only redraws what it shows when it next updates that part of the screen. If you change your money, open and close the menu to see the new amount.

Search tab

Search finds the address where a game keeps a value, by taking a snapshot of memory and narrowing it down step by step. This is the classic cheat-finder workflow.

Setting up

  • 8-bit looks at single bytes (0-255). 16-bit (LE) looks at pairs of bytes, low byte first (0-65535).
  • Regions choose where to look. Work RAM and HRAM are ticked by default and hold nearly every game variable. Add SRAM for battery-backed save data.
  • New search takes the snapshot. Every address in the chosen regions starts as a candidate.
  • Reset throws the search away.

Filtering

Pick a condition and click Filter. Candidates that don't match are removed.

ConditionKeeps addresses whose value
= valueequals the number you type
≠ valuedoesn't equal it
> value, < valueis above or below it
changed, unchangeddiffers from, or matches, its value at the previous step
increased, decreasedwent up or down since the previous step

"Previous step" means the last time you clicked New search or Filter. Each filter compares against that moment, then becomes the new reference.

You don't need to pause while searching. Change the value in-game, then filter.

Results

The line above the table shows how many candidates remain. The table lists up to 100 of them:

  • Value is the current value, refreshed every second once 100 or fewer remain.
  • Previous is the value at your last filter.
  • Click an address to open it in the Memory tab. Use Freeze or Watch to act on it directly.

If a search finds nothing: the game may store the number differently from how it shows it.

  • Big-endian numbers. The 16-bit option reads the low byte first. Pokémon Red stores HP and experience high byte first, so a 16-bit search misses them. Search 8-bit for the low byte instead: for HP under 256, that's the HP itself.
  • BCD numbers. Some games store each decimal digit in half a byte. Pokémon Red does this for money: ₽3,000 is stored as the bytes 00 30 00. To search for it, type the digits as hex, with no #: search = 30.
  • Off-by-one values. A game may store "lives: 3" as 2, or a level as level − 1.

Breakpoints tab

This tab holds the three ways to react to what the game does: breakpoints, watches, and frozen values. Each section has an add row and a list, with a way to remove each entry.

Execution breakpoints

A breakpoint stops the game on the exact instruction at an address, before it runs, even in the middle of a frame. While stopped, memory and registers show the exact state at that moment.

Type an address and click Add:

  • 0150 for addresses in $0000-$3FFF, which are always bank 00.
  • 4A2F for addresses in $4000-$7FFF. The debugger works out which ROM bank you mean by matching the bytes currently there. If the same bytes appear in several banks, it asks you to write the bank yourself.
  • 01:4A2F to give the bank explicitly.
  • A label name such as DisplayTextID, if a symbol file is installed (below).

When a breakpoint hits:

  • The title bar turns red and the status shows the breakpoint.
  • The memory view scrolls to it, with the PC byte in green.
  • Continue resumes. The breakpoint stays set, so it stops again the next time that code runs.
  • Step frame finishes the current frame and stops at its end.

Each breakpoint shows its hit count. A breakpoint added while the game is stopped at another breakpoint says "applying…" until the game moves on to the next frame. Clear all removes every breakpoint.

Breakpoints only go on ROM code ($0000-$7FFF). A breakpoint works by temporarily swapping a marker byte into memory. In ROM that's invisible, but in RAM it would overwrite a game value. To catch a RAM value changing, use a watch instead.

Using label names (.sym files)

If you build a ROM from a disassembly such as pret/pokered, the build also writes a .sym file listing every label and its address. With it installed, you can set breakpoints by name.

  1. Name the symbol file after the ROM: pokered.gbc needs pokered.sym.
  2. Copy it into the server's roms folder. The upload button only accepts ROMs, so use scp pokered.sym luna@cm-pi:~/gbserver/roms/.
  3. Stop the ROM and start it again. Symbols are read when a ROM starts.

The .sym file is plain text, so you can also search it for data addresses. A line such as 00:d347 wPlayerMoney tells you where to point the Memory tab.

Watches

A watch pauses the game when a value does something. Give it an address, a size, and a condition:

ConditionPauses when the value
changesis different from last frame
becomes =becomes the number you give
leaves =was that number and no longer is
goes >, goes <crosses above or below the number

Watches fire once when the condition starts being true, not every frame while it stays true, so Continue doesn't immediately stop again.

Watches are checked at the end of every frame. The status shows the old and new values, for example Watch $D348 changed $30 → $28. The PC it shows is where the CPU was at the end of that frame, not necessarily the instruction that wrote the value. To find that instruction, see the last recipe.

The list shows each watch's current value and how many times it has fired.

Frozen values

A freeze rewrites a value every frame, so the game can't change it for long. Enter an address, a value and a size, then click Freeze. Unfreeze releases it.

If you edit a frozen 8-bit byte in the Memory tab, the freeze keeps your new value.

Limits: 32 breakpoints, 16 watches and 64 frozen addresses at a time.

CPU tab

Shows the Game Boy CPU's registers: A, F, B, C, D, E (8-bit), and HL, SP, PC (16-bit). Below them, the flags from register F light up when set: Z zero, N subtract, H half-carry, C carry.

  • While stopped, the values are exact. While running, they're a snapshot taken between frames.
  • Click a register to change it. Changing PC makes the CPU continue from a different address, which can easily crash the game; save first.
  • View PC in memory opens the Memory tab at the next instruction. View stack opens it at SP.

Recipes

These use the original Pokémon Red. A ROM hack can move things around, so if an address doesn't match, find it with Search or look it up in your .sym file.

Before experimenting, make a save state (Save now in settings) so you can go back if a change breaks something.

Set your money

Money is three BCD bytes at $D347: ₽123,456 is stored as 12 34 56.

  1. In the Memory tab, type D347 and press Go.
  2. In the Poke row, enter D347 as the address and 99 99 99 as the bytes, then click Write. (Typing 99 three times on the selected byte works too.)
  3. Open and close the in-game menu. Your money now reads ₽999,999.

Every half of each byte must be a digit 0-9. 00 50 00 is ₽5,000; 00 5A 00 is not a valid amount.

Find a number you can see: HP

Find where your Pokémon's HP lives, using its value on screen.

  1. Start a battle. Note your Pokémon's HP, for example 44.
  2. In the Search tab, keep 8-bit with WRAM and HRAM, and click New search.
  3. Choose "= value", type #44, and click Filter.
  4. Take a hit. If HP is now 37, filter "= value" with #37.
  5. Repeat until a handful of candidates remain.

Expect about two results. The game keeps one copy of HP in the party data ($D16C-$D16D for the first Pokémon, high byte first) and a separate copy for the Pokémon currently battling.

Find a number you can't see: position

The game never shows your coordinates, but you can still find them by how they change.

  1. Stand outside in a town. Click New search.
  2. Walk one step right. Filter "increased".
  3. Walk one step right again. Filter "increased".
  4. Don't move. Filter "unchanged".
  5. Walk one step left. Filter "decreased".
  6. Repeat until one or two addresses remain. Walk around and watch their Value column follow you.

The same approach finds anything that moves in one direction: a step counter, a timer, the number of an item you use.

Infinite HP

Stop the battling Pokémon from losing HP.

  1. Find the HP addresses with the HP recipe.
  2. Click Freeze next to each result.
  3. Take a hit. The HP bar may flicker, but the value comes straight back.
  4. Unfreeze them in the Breakpoints tab when you're done.

Freezing only holds a value; it doesn't change the game's logic. Some effects, such as fainting checks that run within the same frame as damage, can still happen.

Stop when something changes

Pause the game the moment your money changes.

  1. In the Breakpoints tab, under Watches, enter D348, keep 8-bit, and choose "changes". Click Add.
  2. Buy something in a shop.
  3. The game pauses and the status shows the old and new values.
  4. Click Continue.

$D348 holds the hundreds and thousands digits. Shop prices end in 00, so the last byte ($D349) usually doesn't change when you buy something, but $D348 does.

Stop on a specific piece of code

Freeze the game on the exact instruction that starts a conversation.

  1. Install your ROM's .sym file and restart the ROM (see Using label names).
  2. In the Breakpoints tab, type DisplayTextID and click Add.
  3. Talk to anyone in the game.
  4. The game stops before the text box appears. Open the CPU tab to see the registers at that instant, or click View stack to see where it was called from (the top two bytes are the return address, low byte first).
  5. Click Continue to let the conversation run, then Remove the breakpoint.

If your hack renamed this routine, search the .sym file for another label with an address below 8000.

Sharing a session

Everyone in a session sees the same game, so the debugger follows the session's control rules.

ControllerViewers
View memory and registersYesYes
SearchYesYes, their own search
Edit memory and registersYesNo
Breakpoints, watches, freezesYesNo
Pause, continue, stepYesNo

Everything the controller sets up is cleared, and the game resumes, when:

  • control passes to someone else, including when the controller disconnects;
  • a ROM is loaded, stopped or reset.

This means nobody inherits a paused game or a stray freeze from someone else. Stopping the ROM or loading another one works even while the game is stopped at a breakpoint.

Save states are written with breakpoints removed, so a save made while debugging is always clean.

Pausing freezes the game for every viewer. In a private room that's just you; in the shared game, everyone watching sees it.

Messages

Only the current controller can edit memory
You're a viewer. Use Request control on the player page, or ask the controller to hand it over.
ROM ($0000-$7FFF) is read-only
You tried to edit, poke or freeze ROM. Only RAM can be changed.
Breakpoints go on ROM code ($0000-$7FFF) only
You tried to set a breakpoint in RAM. Use a watch to catch RAM changes.
$4A2F looks identical in 3 ROM banks - enter it as BB:4A2F
The bytes at that address match more than one bank, so write the bank you mean, such as 02:4A2F. Label names from a .sym file avoid this entirely.
Unknown symbol "…" (no .sym file next to this ROM?)
Check the label's spelling, that the .sym file has the same name as the ROM, and that you restarted the ROM after copying it.
$C0A3 has a breakpoint on it - remove it before editing
Remove the breakpoint at that address first.
No ROM running / Needs the pyboy engine
Start a ROM, or switch the ROM's engine to pyboy in the ROM library.
Start a new search first
Click New search before filtering. A search is also cleared if you reconnect.
Debugger state was reset (ROM changed or control moved)
See Sharing a session. Set up your breakpoints and freezes again.
The debugger is disabled on this server
The server owner has set GBSERVER_DEBUGGER to off, or to internal and you're connecting through the public address.
Too many requests - try again in a moment
The server limits how fast the debugger can send requests. Wait a second.
